# POPART.love

Static site for popart.love. Same section structure as bitpopart.com (News, Artist, PopUp, Cards, Stickers, Prints, Shop), with its own Love / Freedom / Joy pop art look and no Bitcoin, Nostr or AI theming.

## Folder

```
POPARTlove/
  build.py            generates every page, the SVG art, sitemap, robots, _headers, CNAME
  assets/css/style.css
  assets/js/site.js   theme toggle, mobile menu, newsletter form
  assets/img/         logo, favicon, placeholder artworks (SVG), cards/ (example card WebPs)
  assets/fonts/       self-hosted Bangers, Barlow Condensed, Space Mono, Inter
  index.html, cards/, popplay/, stickers/, prints/, shop/, news/, artist/, popup/, 404.html
```

## Card Maker

`cards/maker/index.html` is the POPART Card Maker, a single self-contained tool page (it is not generated by `build.py`, edit the file directly). It loads Google Fonts and jsPDF from cdnjs. The six example cards in `assets/img/cards/` were rendered with the maker's own drawing code. The "write card text from the art" button only works inside Claude, so it is hidden on the site.

## Adding a new card

1. Make the card in the Card Maker and export the front and the back as images (WebP, 600x840 works well).
2. Put it in `assets/img/cards/` (for example `my-card.webp` and `my-card-back.webp`). Visitors flip the card between front and back.
3. Add one entry at the top of `data/cards.json` (file, name, theme, series, rarity, run, blurb).
4. Run `python3 build.py`, commit and push. The card appears on the Cards page (the first three also show on the home page).

## Importing cards from the Card Maker

The Card Maker has a "Send cards to popart.love" panel that saves a site file (`popart-site-cards.json`) with the front and back pictures and the details of each card. Import it with:

```
python3 import_cards.py popart-site-cards.json
python3 build.py
```

This writes the pictures to `assets/img/cards/`, adds the card to `data/cards.json` (or updates it, keeping its status and stock) and the card then shows on the Cards page and in the Verify my card list.

## Card stock and the admin

- Each card in `data/cards.json` also has `online`, `offline` and `url` (external shop link, https only). Cards show a Buy online chip (to that link) and an At events chip (to the PopUp page). The admin edits all of these.
- Each card in `data/cards.json` has `status` (`available`, `sold-out`, `coming-soon`) and `left` (copies remaining, or `null` when not tracked). These are the defaults baked into the pages.
- Live stock is kept in Cloudflare KV and served by `worker/index.js` at `/api/stock`. The card pages fetch it on load and override the defaults.
- `/admin/` looks like a 404 page to everyone. The editor only appears when the Nostr extension signs in with the owner key (and an Admin menu link then appears in that browser). Saving sends a NIP-98 signed Nostr event; the worker only accepts the key in `ADMIN_PUBKEY` (`wrangler.jsonc`).
- Deploy with `npx wrangler deploy` (the KV namespace is created on the first deploy).

## Verify my card

`/verify/` checks the card code from the back of the card (see Per-copy verify codes below), not the printed number. The sold list is kept in Cloudflare KV and edited in `/admin/` (Sold serials column, like `1-5, 7`).

## Edit and rebuild

Content lives in `build.py` (page text, `ARTWORKS`, `EXAMPLE_CARDS`, `SHOP_ITEMS`, `NEWS_ITEMS`). After a change:

```
cd POPARTlove
python3 build.py
python3 -m http.server 8765   # preview at http://127.0.0.1:8765
```

### Per-copy verify codes
Each numbered copy can carry its own code, printed on the back of the card and on the Card Maker certificate and mount card. The code is the first 40 bits of HMAC-SHA256(`CODE_SECRET`, `<card file>:<serial>`) written as 8 letters and digits, shown as `8BNK-CW4K`. Set the same secret in the Card Maker (Secret verify key field) and on the site: `wrangler secret put CODE_SECRET`. `/verify/` asks for the code only (no serial): `/api/verify?code=..` makes the codes of all numbered copies from the secret, finds the match and answers card, copy number, whether it is on the sold list and how many times the code was checked. 10 tries a minute per visitor. Without `CODE_SECRET` it answers 503. The card file is the site card id, for example `heart-holder`. Never commit the secret.

The 5 digit holder number is HMAC-SHA256(`CODE_SECRET`, `holder:<card file>:<serial>`) mod 100000. It is printed only on the certificate and mount card. `/api/verify?code=..&holder=..` adds `holderOk` to the answer.

### Admin: PopUp events, stickers and prints
`/admin/` (Nostr sign-in) also edits the PopUp events list and the Stickers and Prints lists. Each save is a signed request, same as card stock. Events have name, date, time, location, link, description and a thumbnail; an event moves to Past events automatically after its date, or when you press Move to past events (it then stays there). Stickers and prints have name, price, link, picture and an Available / Coming soon switch. Pictures are shrunk in the browser to small WebP files and kept in Cloudflare KV (`/api/event-image`). API: `/api/events`, `/api/catalog?kind=stickers|prints` (GET public, PUT admin). While a list is empty the Stickers and Prints pages keep their draft designs.

### Free downloads
`/free/` lists free files uploaded in `/admin/` (Free downloads section): name, category, description, optional thumbnail and the file itself (any type, up to 20 MB, kept in Cloudflare KV). Visitors filter by category and press Download (`/api/file?id=`, always sent as a download). Linked from the Shop page. The list is `/api/catalog?kind=free`.

### Digital files for stickers and prints (free or paid)
In `/admin/`, each sticker or print can carry a digital file (PDF, PNG, zip, up to 20 MB) marked Free download or Paid download. Free files get a "Download to print" button. Paid files are never public: the buyer pays through the item's payment or shop link (any https link: PayPal, Stripe payment link, shop, Lightning page), then you press Download codes on that item, make a code and send it to the buyer. They enter it under Digital downloads on the Shop page (`/shop/#digital`). A code works a set number of times (you choose, default 3) and is checked server side (`/api/download?code=`, 10 tries a minute per visitor). Codes are shown once when made. Delivering codes automatically after payment would need a payment provider webhook, a later step.

## Card prices

In Admin, each card has a Price field (one number, same in euro and dollar). The Cards and Shop pages show one price: euro for visitors in Europe (by browser time zone), dollar for everyone else. Leave it empty to hide the price. Sold-out cards hide it.

## Add and edit cards in Admin

Under "Edit cards" you can add a card (name, web name, theme, series, rarity, run, description, front and back picture), edit any card, or hide/delete one. New cards appear first on the Cards, Shop and home pages. Use the same web name as the card file from the Card Maker so the verify codes match. Changes are stored in KV (`cardlist`) and the pictures at `/api/event-image?id=c-<web name>`. Hidden cards stay verifiable.

## News and quick jump

Admin has a News section: title, date, text and a thumbnail photo. Saved news replaces the starter news on the News page and the home page (newest first). Buttons at the top of Admin jump to each section.

## Collections

Admin has a Collections section: name, short line, thumbnail (the first card is used if none) and the cards in it. Each card row in the Cards table also has "Add to collection" checkboxes, and the main Save changes button saves collection changes too. The Cards page shows the collections as tiles; a click shows only the cards in that collection. Stored in KV `collections`, thumbnails at `/api/event-image?id=k-<id>`.

Collections can also hold stickers and prints (tick them in the collection form; they must be saved in Stickers/Prints first). There is a Collections page (/collections/) and a Collections icon on the home page.

## Look and feel

Headlines use the chunky Chango font with a white fill, black outline and hard shadow. Body text uses Comfortaa. Colour bands with dots (home "Three good vibes only", studio call to action) and a drop cap on the Studio text follow the BangPOP style. Fonts are self-hosted in assets/fonts.

### Collection pages

Every collection has its own page at `/collections/<address>` (for example `/collections/bangpop`). In the Collections form you set the page address, a header picture (saved as `/api/event-image?id=h-<id>`) and the text about the collection. The address is lowercase letters, numbers and dashes, and must be unique. The worker route `/collections/*` serves the Collections page and sets the page title and share text for that collection, so the worker must be redeployed for these addresses to work.
